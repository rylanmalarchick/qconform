qconform report format v0
=========================

Versioned JSON output contract of the checker. Implementable from this
file plus program-format-v0.txt. Draft v0, 2026-07-10; the field set
freezes at v1. JSON conventions (no floats, canonical rationals, i64
bounds) are the same as program-format-v0.txt.

verdict and exit codes
----------------------
  verdict            meaning                          exit code
  pass               no rejections                    0
  fail               at least one fatal rejection     1
  pass_with_repairs  rejections, all vendor_repairable 2
  (no report)        tool error: malformed program,   3
                     invalid descriptor, io, oom

A CI gate chooses its strictness: fail the build on exit >= 1, or
tolerate named repairs by failing only on 1 and 3. Unrealizable is a
normal result; only exit 3 is an abnormal one.

rule ids
--------
snake_case enum names serialized as strings; append-only. A rule id is
never renamed, renumbered, or reused; a retired rule keeps its id
reserved. Numeric ordinals never appear in output. Repair ids follow
the same discipline.

rejection
---------
Every example below is real output. The corpus case that produces it is
named in brackets.

A fatal rejection carries no repair [below-min-length]:

  {"rule": "pulse_length_range", "severity": "fatal", "element": 0,
   "quantity": "time", "value": {"num": 1, "den": 299520000},
   "limit": {"num": 1, "den": 199680000}}

A vendor_repairable rejection names the repair [freq-alias-v6]:

  {"rule": "frequency_range", "severity": "vendor_repairable",
   "repair": "alias_mod_f_dds", "element": 0, "quantity": "frequency",
   "value": {"num": 7188480000, "den": 1},
   "limit": {"num": 4792320000, "den": 1}}

- rule: rule id
- severity: fatal or vendor_repairable
- repair: present when, and only when, severity is vendor_repairable.
  The repair id names what the vendor stack does silently, such as
  quantize_duration. The rule catalog records whether a repair keeps
  experiment semantics. A rejection does not restate that.
  A checker enforces this pairing at descriptor load. Some rules never
  report a repair and others always do, so a descriptor cannot give a
  rule a severity the rule cannot express.
- element: the element id from the program file
- quantity: time, frequency, phase, amplitude, or count
- value, limit: the offending value and the device limit, as exact
  rationals in the SI base unit of the quantity. The units are seconds,
  Hz, turns, full-scale fraction, and dimensionless count. A temporal
  value is converted exactly from ticks to seconds, so a report reads
  the same under any descriptor.

Ordering is deterministic. Rules appear in catalog order. Inside one
rule, elements appear in file order. The same input always produces
byte-identical output.

budgets (class B)
-----------------
Real output [below-min-length]:

  {"budget": "pmem_words", "verdict": "fits",
   "lower_bound": 15, "upper_bound": 16, "limit": 4096}

- fits: upper_bound is at most the limit. The budget stays out of the
  rejection list.
- violates: lower_bound is above the limit. The budget also appears as a
  fatal rejection with quantity count.
- indeterminate: the limit falls between the two bounds. The budget
  appears here and never as a rejection.

A fatal rejection comes only from a proven lower bound. A conservative
estimate never produces one.

coverage manifest
-----------------
The manifest lists every class the checker knows, in registry order, so
its length does not depend on the program. Real output, abridged
[below-min-length]:

  [{"class": "pulse_length_range", "status": "checked"},
   {"class": "readout_length_range", "status": "not_applicable"},
   {"class": "envelope_memory", "status": "not_applicable"},
   {"class": "pmem_words", "status": "checked"},
   {"class": "unconstrained_channel", "status": "not_applicable"}]

A status is checked, not_applicable, unchecked, or indeterminate.

A verdict of pass means one thing. The checker found no violation in the
classes marked checked, against the echoed descriptor at its pinned
versions. It means nothing more.

not_applicable marks a class the program does not exercise. unchecked
marks a class the descriptor declares but does not constrain. A vacuous
pass and an unchecked class are different statements.

descriptor echo
---------------
  "descriptor": {"name": "qick-zcu216-testbench",
                 "firmware": "Fri Aug 29 12:51:57 2025",
                 "software": "qick-0.2.418",
                 "descriptor_version": "0"}

The report echoes the descriptor identification block without changing
it. The descriptor schema fixes the shape. The report always states what
it checked against.

Every string here comes from the descriptor, so a writer escapes the
full set that JSON requires. That is the quote, the backslash, and every
character below U+0020.
