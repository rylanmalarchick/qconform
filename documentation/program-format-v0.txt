qconform program format v0
==========================

Versioned JSON interchange format for pulse programs: exporters produce
it, the checker consumes it. Implementable from this file alone.
Draft v0, 2026-07-10; the field set freezes at v1.

JSON conventions
----------------
- UTF-8, one JSON object per file
- no floats anywhere; every JSON number is an integer
- non-integer quantities are rationals: {"num": N, "den": D} with N, D
  integers, D > 0, gcd(|N|, D) = 1; the sign lives on num. A reader
  rejects non-canonical rationals.
- integers must survive a 64-bit round-trip; values outside i64 are
  rejected. A reader that parses numbers through float64 does not
  conform.
- unknown fields and unknown kinds are validation errors, not warnings
- name strings are nonempty and unique within their array

Top level
---------
  {
    "format": "qconform-program",
    "format_version": 0,
    "channels": [...],
    "frames": [...],
    "waveforms": [...],
    "elements": [...]
  }

A reader that sees a format_version it does not implement errors out;
it never guesses.

channels
--------
  {"name": "d0",
   "unit": {"num": 1, "den": 599000000},
   "sample_unit": {"num": 1, "den": 9584000000}}

- name: the binding key against the device descriptor at check time
- unit: the time base of the channel, as an exact rational number of
  seconds per time unit. It must be strictly positive, so num is above
  zero. Every duration on the channel is an integer count of this unit.
  A non-positive time base is a validation error and not a rejection,
  because it would run the frame clock backwards. An exporter emits the
  unit it knows exactly. QICK uses one tProc tick. Qblox uses 1 ns,
  which is {"num": 1, "den": 1000000000}. Conversion to descriptor ticks
  happens at check time. A duration that does not convert exactly is a
  grid rejection, not an input error.
- mixer_frequency: the digital mixer setting on this channel, as a
  rational number of Hz. It is signed, because a mixer can sit below the
  band as easily as above it. Declare it only when the channel has a
  mixer.
  A descriptor constraint marked post_mixer is checked against the
  frequency the device sees, which is the requested frequency minus this
  value. An interpolated QICK generator works that way. A program that
  plays on such a channel and declares no mixer_frequency is a validation
  error: the checker cannot know the band, and assuming zero would accept
  programs the toolchain refuses.
- sample_unit: seconds per waveform sample on this channel. It must be
  strictly positive, on the same terms as unit. It is required only when
  a samples waveform plays here. The timing unit and the sample rate
  differ on real hardware, because a QICK generator runs many samples
  per tProc tick, so the format declares them separately.

frames
------
  {"name": "q0_xy", "channel": "d0",
   "frequency": {"num": 4900000000, "den": 1},
   "phase": {"num": 0, "den": 1}}

- a frame is a clock plus NCO state on one channel
- frequency: initial value, rational Hz
- phase: initial value, rational turns (1 turn = 2 pi rad); turns keep
  phase arithmetic exact where radians cannot
- targets without native frames (QICK) get one frame per channel from
  the exporter; the descriptor declares frames native or compiled-away

waveforms
---------
  {"name": "flat", "kind": "const",
   "amplitude": {"num": 1, "den": 2}}

  {"name": "arb", "kind": "samples", "full_scale": 32767,
   "i": [0, 16384, 32767], "q": [0, 0, 0]}

- amplitude: a dimensionless full-scale fraction, as a rational. The
  nominal range is -1 to 1. A value outside that range is not a
  validation error. The vendor toolchain accepts it and truncates the
  gain, so the checker reports it under the amplitude_range rule
  instead. Deleting that finding would remove the reason the checker
  exists.
- samples: integer DAC-code arrays; full_scale declares the code that
  means 1.0; i and q have equal length; one entry per sample_unit
- parametric kinds (gaussian, drag, flat_top) are reserved for a later
  version; v0 exporters lower them to samples

elements
--------
Ordered list; the order is the timing model. Time is instruction-
ordered per frame: play, capture, and delay advance their frame's clock
by duration; shift_phase and set_frequency take zero time; barrier
aligns clocks. Absolute times are computed by the checker's resolve
pass and never appear in the file.

Every element has:
- id: unsigned integer, unique within the file, assigned by the
  exporter. Rejections cite ids, never list positions, so the checker's
  internal program representation can change without breaking the
  report contract.
- kind: play | capture | delay | barrier | shift_phase | set_frequency

  {"id": 0, "kind": "play", "frame": "q0_xy",
   "waveform": "flat", "duration": 60}

  {"id": 1, "kind": "capture", "frame": "r0_ro", "duration": 1200}

  {"id": 2, "kind": "delay", "frame": "q0_xy", "duration": 100}

  {"id": 3, "kind": "barrier", "frames": ["q0_xy", "r0_ro"]}

  {"id": 4, "kind": "shift_phase", "frame": "q0_xy",
   "phase": {"num": 1, "den": 4}}

  {"id": 5, "kind": "set_frequency", "frame": "q0_xy",
   "frequency": {"num": 4850000000, "den": 1}}

- duration: integer count of the frame's channel unit
- a samples waveform states its own length; whether duration * unit
  equals sample count * sample_unit is a device rule (vendors zero-pad
  the mismatch silently), never an input error
- barrier with frames omitted aligns every frame in the file
- shift_phase is virtual-Z; phase in rational turns, added to the frame
- capture returns data; result naming and binning are target scope, not
  program scope, in v0

validation errors vs rejections
-------------------------------
Malformed input is a tool error (exit 3; see report-format-v0.txt):
duplicate ids or names, dangling frame/channel/waveform references,
non-canonical rationals, non-positive unit or sample_unit, unknown
fields or kinds, missing sample_unit under a samples waveform, and a
missing mixer_frequency on a channel whose descriptor constraint is
post_mixer.

A well-formed program that violates a device limit is never a tool
error. It produces rejections.

example: QICK-flavored (unit = one tProc tick)
----------------------------------------------
{
  "format": "qconform-program",
  "format_version": 0,
  "channels": [
    {"name": "d0",
     "unit": {"num": 1, "den": 599000000}},
    {"name": "r0",
     "unit": {"num": 1, "den": 599000000}}
  ],
  "frames": [
    {"name": "q0_xy", "channel": "d0",
     "frequency": {"num": 4900000000, "den": 1},
     "phase": {"num": 0, "den": 1}},
    {"name": "r0_ro", "channel": "r0",
     "frequency": {"num": 6100000000, "den": 1},
     "phase": {"num": 0, "den": 1}}
  ],
  "waveforms": [
    {"name": "flat", "kind": "const",
     "amplitude": {"num": 1, "den": 2}}
  ],
  "elements": [
    {"id": 0, "kind": "play", "frame": "q0_xy",
     "waveform": "flat", "duration": 60},
    {"id": 1, "kind": "barrier", "frames": ["q0_xy", "r0_ro"]},
    {"id": 2, "kind": "capture", "frame": "r0_ro", "duration": 1200}
  ]
}

example: Qblox-flavored (unit = 1 ns)
-------------------------------------
{
  "format": "qconform-program",
  "format_version": 0,
  "channels": [
    {"name": "cluster0_qcm0_o1",
     "unit": {"num": 1, "den": 1000000000},
     "sample_unit": {"num": 1, "den": 1000000000}}
  ],
  "frames": [
    {"name": "q0_drive", "channel": "cluster0_qcm0_o1",
     "frequency": {"num": 400000001, "den": 4},
     "phase": {"num": 0, "den": 1}}
  ],
  "waveforms": [
    {"name": "arb", "kind": "samples", "full_scale": 32767,
     "i": [0, 16384, 32767, 16384],
     "q": [0, 0, 0, 0]}
  ],
  "elements": [
    {"id": 0, "kind": "shift_phase", "frame": "q0_drive",
     "phase": {"num": 1, "den": 4}},
    {"id": 1, "kind": "play", "frame": "q0_drive",
     "waveform": "arb", "duration": 4},
    {"id": 2, "kind": "delay", "frame": "q0_drive", "duration": 100}
  ]
}
